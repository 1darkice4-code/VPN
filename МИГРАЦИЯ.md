# МИГРАЦИЯ НА НОВУЮ АРХИТЕКТУРУ

## Что изменилось

Проект переделан под правильную продакшн архитектуру:
- ❌ Убран контейнер `linuxserver/wireguard`
- ✅ WireGuard теперь работает как системный сервис
- ✅ wgREST работает с системным WireGuard
- ✅ Упрощена конфигурация Docker

## Пошаговая миграция

### 1. Остановить старые контейнеры

```bash
# Остановить все контейнеры
docker-compose down

# Удалить старые volumes (опционально)
docker volume rm vpn_wgrest_data
```

### 2. Установить WireGuard как системный сервис

```bash
# Получить обновления
git pull origin main

# Сделать скрипт исполняемым
chmod +x install_wireguard_service.sh

# Запустить установку WireGuard (требует root)
sudo ./install_wireguard_service.sh
```

### 3. Запустить новые контейнеры

```bash
# Запустить обновленные контейнеры
docker-compose up -d

# Проверить статус
docker-compose ps
```

### 4. Проверить работу системы

```bash
# Сделать скрипт проверки исполняемым
chmod +x check_vpn_system.sh

# Запустить полную проверку
./check_vpn_system.sh
```

## Troubleshooting

### Если WireGuard не запускается
```bash
# Проверить конфигурацию
sudo wg-quick strip wg0

# Переустановить сервис
sudo ./install_wireguard_service.sh
```

### Если wgREST не видит устройство
```bash
# Проверить статус WireGuard
sudo systemctl status wg-quick@wg0

# Перезапустить wgREST
docker-compose restart wgrest
```

### Если бот не работает
```bash
# Проверить доступность wgREST
curl http://localhost:8080/version

# Проверить логи бота
docker logs vpn_bot
```

## Откат (если нужно)

Если что-то пошло не так, можно откатиться:

```bash
# Остановить WireGuard сервис
sudo systemctl stop wg-quick@wg0
sudo systemctl disable wg-quick@wg0

# Вернуться к предыдущей версии
git checkout HEAD~1
docker-compose up -d
```
