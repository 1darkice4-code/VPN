## ✅ Что было сделано

### 1. wgREST настроен на host networking
**Причина**: wgREST требует доступ к WireGuard устройству через IPC

```yaml
wgrest:
  network_mode: host  # ✅ Доступ к WireGuard на хосте
```

### 2. Бот подключен к wgREST
**URL**: `http://host.docker.internal:8080`

```yaml
vpn_bot:
  extra_hosts:
    - "host.docker.internal:host-gateway"
  environment:
    WGREST_URL: http://host.docker.internal:8080
```

### 3. Удален PEERS=10
Пиры создаются **только через wgREST API**, а не при старте контейнера

## ⚠️ Важно

### Доступ к WireGuard устройствам

wgREST работает с **реальными** WireGuard устройствами на хосте через:
- Host networking
- IPC (wgctrl)

Поэтому он может видеть и управлять:
- ✅ wg0 из контейнера linuxserver/wireguard
- ✅ Любыми WG устройствами на хосте

### Если WireGuard устройство не создано

wgREST автоматически создаст его при первом запросе от бота.

### Порты

- **wgREST**: 8080 (host network)
- **WireGuard**: 51830/udp
- **PostgreSQL**: 5432

## 🐛 Troubleshooting

### Ошибка: "failed to get wireguard device"
```
wgREST не видит WireGuard устройства
```

**Решение**:
```bash
# Проверьте что WireGuard контейнер запущен
docker-compose ps wg

# Проверьте что устройство wg0 существует
docker exec wg ip link show wg0

# Перезапустите wgREST
docker-compose restart wgrest
```

### Ошибка: "connection refused" от бота к wgREST
```
Бот не может подключиться к wgREST
```

**Решение**:
```bash
# Проверьте что wgREST слушает на правильном порту
docker logs wgrest | grep "server started"

# Проверьте доступность wgREST с хоста
curl http://localhost:8080/version

# Проверьте URL в боте
docker exec vpn_bot printenv WGREST_URL
```

### Ошибка: 501 Not Implemented
```
wgREST не может создать устройство
```

**Решение**:
wgREST не создает устройства автоматически. Нужно создать wg0 вручную или через linuxserver/wireguard контейнер.

```bash
# Убедитесь что WireGuard контейнер создал wg0
docker exec wg cat /config/wg0.conf
```
